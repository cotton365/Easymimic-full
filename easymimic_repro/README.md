# EasyMimic 复现 · 裸手示教 → JAKA Zu3 末端指令

> **English summary.** A partial, self-contained reproduction of the *action-representation* half of EasyMimic: 21 hand keypoints → 8-D end-effector command (position + rotation vector + gripper opening) → six joint angles for a JAKA Zu3 arm, with a real two-finger gripper asset and a 50 Hz waypoint replay verified in MuJoCo (simulation only, nothing has run on real hardware). The current execution entry point is `experiments/pose_replay.py` + `configs/waypoints_cube_lift.json`; the older synthetic-hand closed loop is retired to `legacy/` (§3.5). Video ingestion, camera / hand-eye calibration, dataset writing and the learned policy are **not** implemented. Four scripts pass on this machine with exit code 0, and every number in §4 can be regenerated by one command.

**一句话**：把「手怎么动」翻译成「机械臂六个关节怎么动、夹爪开到多大」，并且每一个数字都能被本仓库的一条命令重新算出来。

**状态**：T1–T10 之后。现役验收链是：人手 21 点 → 8 维末端指令（数值层）→ 6 关节角（数值层）→ 真夹爪资产上的抓取抬升（仿真层）→ JSON 示教表 50 Hz 回放（执行层）。旧的合成手闭环脚本已退役并搬到 `legacy/`，它绑定的占位夹爪在 T7 被换掉了（§3.5）。

## 1. 这是什么，不是什么

用户最初的设想是一条流水线：

```text
视频 → 手部特征(21 关键点) → 打点表示 → 末端指令 → 关节角 + 夹爪量 → 执行
```

| 段 | 在本仓库 | 状态 |
|---|---|---|
| ① 接收视频 | 无代码 | 未开始 |
| ② 手部特征识别（HaMeR，21×3 + 腕部 6DoF）| 无代码；假定已就绪 | 外部依赖，未移植 |
| ③ 打点表示：21 点 → 8 维 EE | `src/ee_retarget/hand_to_ee.py` | 已验收（数值）|
| ④ 末端指令：8 维 EE → 6 关节角 | `src/ee_retarget/ik_jaka_zu3.py` | 已验收（数值）|
| ⑤ 关节角 + 夹爪量 → 仿真执行 | `experiments/pose_replay.py` + `configs/waypoints_cube_lift.json` | 已验收（仿真，开环）|
| ⑥ 真机后端 | 无代码 | 未开始 |

资产与工具：`assets/jaka_zu3/`（自写 MJCF，含 T7 换上的真夹爪 `gripper_real.xml`）、`experiments/t1_verify.py`（资产 / 抓取 / 离屏渲染验收）、`tests_ee/test_ee_pipeline.py`（12 组断言）。

**是**：一个可独立运行、可复跑的「手 → 8 维末端动作 → 6 关节角 → MuJoCo 执行」链条，外加一套能在 MuJoCo 里真正夹起 2×3×3 cm 方块的 JAKA Zu3 资产（真夹爪，不是占位件）。

**不是**：不是完整的 EasyMimic，不含策略网络、数据集、视频解码、标定工具，**也没有在真机上跑过一次**——本文档里「实测」一律指仿真实测。

**也不是**：③④ 的实现是否与论文逐条等价，本次没有核对公式（未验证）；能确认的只是接口划分（8 维动作、thenar 锚点、平面拟合）与论文一致。

## 2. 数据流（读代码时按这个顺序）

```text
21 keypoints (21,3) + R_wrist (3,3) + T_base_cam (4,4)
        │
        │  hand_to_ee.hand_to_ee()                    ← 本仓库 · 已验收
        ▼
8 维动作 ee8 = [pos(3), rotvec(3), g(1), reserved(1)]   in robot base frame
        │
        │  ik_jaka_zu3.JakaZu3IK.solve_robust()       ← 本仓库 · 已验收
        ▼
6 关节角 q (rad) + 夹爪 ctrl = g * 0.9 (rad)
        │
        │  experiments/pose_replay.py                 ← 本仓库 · 已验收（T9）
        ▼
MuJoCo scene: 50 Hz set-points → position actuators → contacts → cube rises
```

- `pos`：**thenar 锚点**（大鱼际点，拇指与食指根部之间）在基座系下的位置，不是手腕。
- `rotvec`：手掌平面的姿态，X 轴 = 食指 MCP→PIP，Z 轴 = 5 点拟合平面的法向。
- `g`：**g = 1 张开，g = 0 闭合**（与 `hand-6dof-pipeline/retarget/so101.py:110` 的 `norm` 语义一致）。
- 第 8 维保留位恒为 0，给将来加「第二指/吸盘/力控」留位。
- 任一关键点为 NaN 时，整帧 8 维全 NaN（不补零、不插值）——下游靠 `info["valid"]` 过滤。
- 关节角是**执行层**，不是动作空间：6 轴臂的 IK 有多解，把它塞进学习信号会污染数据集。
- 夹爪量纲：`g` 的方向没变（1 = 全开），但执行量从占位滑轨的 0.04 m 换成了真夹爪 `joint_7` 的弧度——`ctrl = g * 0.9`，见 `src/pose_cmd/replay.py:40` 的 `GRIPPER_CONFIG` 与 `:102-105` 的 `g_to_ctrl`；`joint_7` 的合法范围就是 0..0.9 rad（`assets/jaka_zu3/gripper_real.xml:68`）。

### 3.7 直接用 MuJoCo 界面看这个场景（零代码）

不经过本仓库任何脚本，只用 MuJoCo 自带的 Simulate 界面打开同一份场景：

```bash
cd /home/zh/Desktop/EasyMimic/easymimic_repro
~/miniconda3/envs/mujoco/bin/python -m mujoco.viewer --mjcf=assets/jaka_zu3/scene_cube_bowl.xml
```

上面是作者本机的绝对路径；换成你自己的解释器、在仓库根目录跑等价：

```bash
python -m mujoco.viewer --mjcf=assets/jaka_zu3/scene_cube_bowl.xml
```

打开之后：

- **能**：右侧 Control 面板是 7 个执行器滑条（`joint_1` … `joint_7`），拖滑条直接把臂摆到想要的姿态；`joint_7` 是夹爪，0 = 张开，0.9 = 闭合。鼠标左键拖 = 转相机，Shift + 拖 = 平移，滚轮 = 缩放。
- **不能**：滑条是**关节空间**的，没有 IK、没有 Cartesian 控制，拖出来的姿态不会自动保存。要按末端 xyz + 姿态 + 夹爪开合（8 维）来驱动，用 `experiments/pose_replay.py` 的航点表（§3.3 第 3 条）。
- 这个界面自己的键位：Space = 暂停 / 继续，Backspace = 重置，Tab = 切左右面板，`[` `]` = 切执行器分组显示，Esc = 退出。
- 资源路径全部相对于文件本身解析（`assets/jaka_zu3/robot.xml:8` 的 `meshdir` 指向上游 `third_party/jaka-zu3-mujoco/assets/jaka_zu3_meshes`），所以任意 cwd 都能加载；前提是先跑过 §3.2 的 `scripts/fetch_third_party.sh`。

## 6. 关键设计决策（改了就会坏的原因）

1. **动作空间 = 8 维 EE，不是 6 关节。** JAKA 真机本来吃笛卡尔指令；6 轴 IK 多解，且 joint_2/joint_4 限位只有 −1.48~4.62 rad，把 IK 结果当学习目标等于把求解器的不确定性写进数据集。
2. **锚点是 thenar（大鱼际），不是手腕。** 论文的 thenar 锚点 = 拇指 PIP 与食指 MCP 的中点。21 点约定里没有「拇指 PIP」，取**拇指 IP（idx 3）**代替，所有 landmark 索引都做成模块常量，换手模型时只改表。
3. **平面法向用 SVD，X 轴用食指 MCP→PIP。** 5 个点（食指 5,6,7,8 + 拇指 3）拟合平面，最小奇异向量取法向；法向有 ±歧义，用腕部参考轴 `R_wrist[:,2]` 消歧，翻转后 Y 由 `Z×X` 重算，保证 det 恒为 +1（右手系，IK 里不可省）。
4. **g 的方向钉死为「1 = 张开」，量纲随真夹爪变成 rad。** 与 `hand-6dof-pipeline/retarget/so101.py:110` 的 `norm` 一致；仿真里 `ctrl = g * 0.9`（0 = 闭合、0.9 rad = 全开），见 `src/pose_cmd/replay.py:40` 与 `:102-105`。反向就是这次交接最容易犯的错。
5. **TCP 偏移现在是 0，因为 `site tool0` 被放到了捏合中心。** `robot.xml:142` 的 `pos="0.0172 -0.0035 0.127"`，t1_verify 实测 tool0 距固定指内面 0.01000 m。历史（已失效）：占位夹爪时代 tool0 在法兰上、捏合中心在 `(0, -0.0325, 0)`，需要 32.5 mm 力臂加 `Jp = Jp - skew(R@t)@Jr` 的雅可比修正；那段代码作为 `JakaZu3IK(tcp_offset=...)` 的参数保留着（默认 None），现役场景不传它。
6. **阻尼是相对的。** `λ_abs = λ_rel * sqrt(trace(JJᵀ)/6)`。绝对 `λ = 1e-3` 在近奇异位形上实测单步 |dq| 达 127.86 rad、成功率掉到 48/100（`src/ee_retarget/ik_jaka_zu3.py:12` 起有记录）。
7. **NaN 全帧传播，绝不补零。** 补零会造出一条「机器人回原点」的假轨迹，训练时比丢帧更毒。
8. **不用 mink / qpsolvers。** 依赖只有 mujoco + numpy；DLS 在一百个随机目标上已经打满，装 QP 求解器换不来精度。
9. **历史（已失效）：动作姿态是「手坐标系」，IK 打的是 tool0，中间差一个 `Rz(90°)`。** 换算函数 `hand_to_gripper()` 随闭环脚本一起退役到 `legacy/closed_loop/synth_hand.py`。现役的示教表直接给 base 系下的 8 维指令，不再经过「手坐标系」；别把 `legacy/` 里那个常数矩阵当成现役约定。

## 7. 坐标系与几何（改资产前必看）

- 世界 +z 向上，桌面顶面精确在 `z = 0.80` m（`scene_cube_bowl.xml:18` 的 `table_top`：`pos z=0.78` + `size z=0.02`），机器人基座也在这一层（`exclude Link_0 / table`）。
- `site tool0` 在 `assets/jaka_zu3/robot.xml:142`，`pos="0.0172 -0.0035 0.127"`（相对它所在的 body），位置就是两指捏合中心；因此 TCP 偏移为 0。
- 夹爪：`joint_7` 是 hinge，`axis="0 -1 0"`、`range="0 0.9"`（`gripper_real.xml:68`）；执行器 `gripper_actuator` 是 position 型，`kp=18`、`kv=0.8`、`ctrlrange="0 0.9"`、`forcerange="-0.8 0.8"`（`robot.xml:170`）。实测两指 pad 盒间距：q=0 时 0.00049 m（闭合）、q=0.9 时 0.06329 m（张开），行程 0.06280 m。
- 闭合夹 2×3×3 cm 方块时实测 pad gap = 0.01871 m（捏合方向 0.02000 m，接触穿透 1.29 mm）；靠 `condim=4` 的摩擦夹住，8 g 的方块能抬 0.09921 m 不掉（t1_verify）。
- 方块是**长方体不是立方体**，这是夹爪几何逼出来的：`tool0` 距固定指内面只有 10 mm（上一行），捏合方向（x）的宽度因此只能是 20 mm，再宽下探时固定指就会插进方块里。y/z 加宽是免费的，而且直接改善可抓性：两指只有 16 mm 高，方块 30 mm 高，垂直对准窗口从 ±2 mm 放宽到 ±7 mm。想真正 30 mm 见方，必须把整条抓取列整体侧移 `h − 0.0094` m（实测：h=0.015 时侧移 6.2 mm），那会连带改示教表与 t1_verify 的对准判据。
- 视觉网格 `group=1/2`、`contype=0 conaffinity=0`；碰撞用 capsule/cylinder 代理，`group=3`、`contype=1 conaffinity=1`。整 STL 当碰撞体在 8 GB 机器上又慢又不稳。
- home keyframe `qpos="0 0.15 0 0 0 0 0.9"`：全零位时法兰会插进桌面，`joint_7 = 0.9` 是全开。
- `meshdir` 写在 `robot.xml:8`，相对**该文件自身**解析，所以模型从任何 cwd 都能加载；但 `JakaZu3IK` 仍然要求绝对路径（`src/ee_retarget/ik_jaka_zu3.py:220-224` 直接 `raise ValueError`）。这条限制原本是为了躲开上游模型 `meshdir` 泄漏进 include 的坑，现在默认路径已换成仓库内的 `robot.xml`，它是保守约束而不是必需——别再靠它解释加载失败。

**MuJoCo 的两个 include 坑**（都在 3.16.0 上实测过）：

- `<include>` 只 splice **根元素的子元素**。被 include 的文件若以单个 `<body>` 为根，被丢掉的正是这个 body：它的 geom 会被上提到父节点（实测 `nbody=1`，球体直接挂到 world）。所以 `gripper_real.xml` 用 `<gripper_real_fragment>` 包一层，让 `<body>` 成为「子元素」而幸存；包裹层的名字会被忽略，叫什么都行。退役的 `gripper_pg2.xml` 用的是同一招（`<gripper_pg2_fragment>`）。
- `<actuator>` 只能写在文档根。写进被 include 的片段里（嵌在 body 内或与 body 并列都试过）**不是静默丢弃，而是硬报错**：`XML Error: Schema violation: unrecognized element Element 'actuator'`。所以 `gripper_actuator` 声明在 `robot.xml:170`，`gripper_real.xml` 里只有 body/joint/geom。

### 12.3 映射（与代码里的注释一一对应）

    p_cmd = p_neutral + gain * (anchor_now - anchor_ref)
    R_cmd = R_neutral @ (R_ref^T @ R_now)
    ctrl  = g_to_ctrl(g_norm)              # 1 = 张开，0 = 捏合

- `anchor_ref` / `R_ref` 在第一个可用手型处校准：整条链路只用相对量，因此不需要手眼外参，
  `T_base_cam` 取单位阵。
- neutral 取 `configs/waypoints_cube_lift.json` 的 `approach` 位姿（位置 [0.474, 0.0435, 0.91]，
  姿态 Ry(pi)）：启动时把 plant teleport 到该位姿，所以第一拍指令不会拽着机械臂跳变。
  不能用 home 关键帧的 FK 当 neutral——在那个位姿上强制抓取朝向时，沿 +X 的 4 cm 位移解不出来
  （最好残差 2.77 mm / 1.00 deg），换成 approach 位姿后 6 个方向全部收敛。
- 手丢失 / 关键点 NaN → 冻结上一条指令（NaN 绝不进 IK），超过 `--lost-timeout` 仍在窗口里标红；
  目标按球面半径 0.15 m 与 z >= 0.80 m（桌面）钳制。

### 12.4 本机未验证的部分

「依赖缺失 → 打印准确的 pip 命令并退出 1」「--probe 打不开设备 → 4 条中文排查提示并退出 1」
「--selftest 全绿并给出末端误差数值」。第一次上台请按 12.2 的顺序，先跑第 1 步。
